## Decisions required before merging

1. Confirm, without revealing its value, that USE_LLM_API currently selects
   API mode. Upstream removed the old Qwen/llama-cpp local generation path.
   False, blank or unset mode stops before constructing Executor; this draft
   does not silently switch local inference to a paid API. If local mode is
   needed, restore it in a follow-up before merging.
2. Review non-secret REPOSITORY and REF. Blank values, this fork plus main,
   or refs/heads/main are supported. Other overrides stop before the step
   with production credentials; do not change actual repository variables
   until the intended checkout target is agreed.
3. Confirm the existing non-secret LANGUAGE, SEND_EMPTY and ZOTERO_IGNORE
   values from repository settings. Their names and semantics are preserved,
   but their actual values could not be read in this session: the connector
   excludes variables endpoints and the Mac browser connection failed.
   No guesses were inserted.
4. CUSTOM_CONFIG migration is optional and deferred. A future change should
   explicitly opt into YAML settings, use environment references for Secrets,
   and review the different include_path/ignore_path glob semantics. Do not
   paste secret values into an Actions variable.

## Workflow safety and changed behavior

Only isolated tests run on pushes to upgrade/** or PRs targeting main.
They receive no production credential environment and block real socket
connections during tests. The public tiktoken vocabulary is cached as
test setup. Slow model-download tests are excluded. The former manual
Test workflow is now an offline suite, because upstream debug mode still
sends email. The daily and keep-alive jobs are restricted to main; no
production workflow was dispatched. No Zotero private library, SMTP server
or paid LLM API was accessed.

Upstream changes paper parsing, prompts, dependencies and Python (3.13+);
retaining settings does not guarantee identical summaries or rankings.
The legacy API request retains temperature=0 and omits the new forced
max_tokens=16384. Upstream retries/fallback behavior differs from the old
API request path and requires later operational verification.

## arXiv robustness and limits of verification

Upstream PR #301 (merged 2026-09-28) constructs metadata from RSS directly,
avoiding the secondary metadata query responsible for one class of HTTP
406. This is separate from the October 5 source-download/affiliations
failure described by the user. New code has tar extraction timeouts,
tar -> HTML -> PDF fallback, abstract fallback for failed TLDRs, and None
fallback for failed affiliations. These source paths were inspected, but
the user's October 5 failure was not reproduced and is not claimed fixed.
